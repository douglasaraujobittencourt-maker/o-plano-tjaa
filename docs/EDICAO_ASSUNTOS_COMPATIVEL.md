# Edição e exclusão de assuntos
O modal não condiciona Editar/Excluir à presença da coluna subjects.tribunal_data. Se a estrutura já existir, utiliza a RPC atual e mantém o ID. Se não existir (ou o RPC estiver ausente), armazena somente as personalizações individuais de assuntos existentes via Supabase Auth updateUser, na conta autenticada do mesmo projeto configurado no client. Não depende de localStorage como fonte de persistência nem de uma nova migração. Os metadados não são usados para controle de acesso. A projeção de getSubjects combina catálogo e personalizações e preserva os IDs; a remoção apenas oculta o item das listas e não apaga sessões ou revisões. O nome histórico de cada sessão permanece como foi registrado. Mudanças em assuntos já personalizados continuam válidas após migração. Adicionar novos assuntos permanece dependente da estrutura de alocação de IDs já existente. Erros de RLS ou FK são reportados, não contornados. Testes automatizados usam mocks; validar uma edição/exclusão com conta autenticada no banco real após deploy.
